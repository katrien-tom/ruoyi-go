- [ ] **Step 2: Write the architecture and request-flow sections**

Add content to `AGENTS.md` that explains:

```md
- `cmd/main.go` owns startup sequencing only.
- `internal/app` stores shared infrastructure dependencies such as MySQL and Redis clients.
- `internal/router` owns Gin setup, middleware registration, and module registration.
- `internal/modules/<name>` contains module-local `router`, `handler`, `service`, `repository`, `entity`, `dto`, and `vo` files as needed.
- `internal/middleware` owns request ID, logging, recovery, JWT auth, and permission checks.
- `pkg/*` contains reusable infrastructure and must not depend on `internal/modules`.
- Request flow is `router -> middleware -> handler -> service -> repository -> response`.
```

- [ ] **Step 3: Write the module convention and code-style sections**

Add content to `AGENTS.md` that requires:

```md
- New modules live under `internal/modules/<name>`.
- Handlers bind/validate input, call services, and map errors to `pkg/response`.
- Services own business rules and domain errors.
- Repositories own persistence and use `WithContext(ctx)` for GORM queries.
- `context.Context` is passed downward from handlers via `c.Request.Context()`.
- Shared responses use `pkg/response`; new business codes extend `pkg/response/code.go`.
- Shared logging uses `pkg/logger`; avoid ad-hoc `fmt.Println`.
- Comments explain intent or constraints, not obvious line-by-line actions.
```

- Do not let `pkg` depend on `internal/modules`.

6. Config or SQL updates were synced when needed.
7. The result was formatted and verified.
